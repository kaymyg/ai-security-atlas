Silence a finding on one line with `# atlas: ignore[RULE_ID]` (or `// atlas: ignore[RULE_ID]`).

### VIBE001

**LLM output is executed as code** · severity: critical · CWE-94

**Fix:** Never eval/exec model output. Parse it into a fixed set of allowed actions instead.

### VIBE002

**Untrusted input placed in an LLM system prompt** · severity: medium · CWE-77

**Fix:** Keep the system prompt constant. Put user text in a separate user message and treat it as data.

### VIBE003

**LLM output passed to a shell command** · severity: critical · CWE-78

**Fix:** Map model output onto an allow-list of commands; never run it directly.

### VIBE010

**eval()/exec() on dynamic input** · severity: high · CWE-95

**Fix:** Use ast.literal_eval for data, or a dispatch table for actions.

### VIBE011

**subprocess with shell=True** · severity: high · CWE-78

**Fix:** Pass a list of arguments and drop shell=True.

### VIBE012

**os.system/os.popen with a built string** · severity: high · CWE-78

**Fix:** Use subprocess.run([...]) with an argument list.

### VIBE013

**SQL query built with string formatting** · severity: high · CWE-89

**Fix:** Use parameterised queries: cursor.execute("... WHERE id = %s", (id,)).

### VIBE014

**Unsafe deserialisation (pickle)** · severity: medium · CWE-502

**Fix:** Don't unpickle data you didn't create. Use JSON for anything from outside.

### VIBE015

**yaml.load without a safe loader** · severity: medium · CWE-502

**Fix:** Use yaml.safe_load().

### VIBE016

**TLS certificate verification disabled** · severity: high · CWE-295

**Fix:** Remove verify=False. Point at a CA bundle if you use a private CA.

### VIBE017

**Debug mode enabled in web app** · severity: medium · CWE-489

**Fix:** Read debug from an env var and keep it off in production.

### VIBE018

**File path built from request data** · severity: high · CWE-22

**Fix:** Resolve the path and check it stays inside an allowed folder (or use werkzeug.secure_filename).

### VIBE019

**Outbound request to a user-supplied URL** · severity: medium · CWE-918

**Fix:** Allow-list hosts before fetching user-supplied URLs.

### VIBE030

**eval() or new Function()** · severity: high · CWE-95

**Fix:** Avoid eval; use JSON.parse for data or a lookup table for behaviour.

### VIBE031

**Raw HTML injection (XSS risk)** · severity: medium · CWE-79

**Fix:** Render text, or sanitise with DOMPurify before injecting HTML.

### VIBE032

**child_process command built from a string** · severity: high · CWE-78

**Fix:** Use execFile/spawn with an argument array.

### VIBE033

**SQL built with a template literal** · severity: high · CWE-89

**Fix:** Use placeholders ($1, ?) or your ORM's tagged template helper.

### VIBE034

**TLS certificate verification disabled** · severity: high · CWE-295

**Fix:** Remove rejectUnauthorized:false / NODE_TLS_REJECT_UNAUTHORIZED=0.

### VIBE035

**Server secret exposed to the browser bundle** · severity: high · CWE-200

**Fix:** Variables with NEXT_PUBLIC_/VITE_/REACT_APP_/EXPO_PUBLIC_ are shipped to every visitor. Keep secrets server-side.

### VIBE050

**Insecure random used for a secret value** · severity: medium · CWE-330

**Fix:** Use secrets.token_urlsafe() (Python) or crypto.randomUUID()/getRandomValues() (JS).

### VIBE051

**JWT signature check disabled or 'none' algorithm** · severity: high · CWE-347

**Fix:** Always verify signatures and pin the expected algorithm.

### VIBE052

**CORS allows any origin** · severity: medium · CWE-942

**Fix:** List the exact origins that may call your API.

### VIBE053

**CSRF protection disabled** · severity: medium · CWE-352

**Fix:** Keep CSRF protection on for any cookie-authenticated endpoint.

### VIBE054

**Unfinished security TODO left in code** · severity: low · CWE-1188

**Fix:** AI assistants often leave the hard part as a TODO. Finish it or track it before shipping.

## AI agent / MCP permissions and trust

| ID | Severity | Rule |
|---|---|---|
| [AGT001](#agt001) | high | Credential hard-coded in an MCP server config |
| [AGT002](#agt002) | medium | MCP server launched from an unpinned package |
| [AGT003](#agt003) | high | MCP server given access to the whole disk or home folder |
| [AGT004](#agt004) | medium | Remote MCP server over unencrypted HTTP |
| [AGT005](#agt005) | high | MCP server container runs privileged or with the Docker socket |
| [AGT010](#agt010) | high | AI agent approval prompts disabled |
| [AGT011](#agt011) | high | AI agent pre-approved to run any shell command |
| [AGT012](#agt012) | medium | AI agent pre-approved for a risky command |
| [AGT013](#agt013) | medium | All project MCP servers trusted automatically |
| [AGT014](#agt014) | medium | AI agent run with approvals disabled in a script or CI |
| [AGT020](#agt020) | medium | AI agent in CI triggered by untrusted input |
| [AGT030](#agt030) | high | Suspicious instruction in an AI agent rules file |
| [UNI001](#uni001) | critical | Invisible Unicode tag characters (hidden AI instructions) |
| [UNI002](#uni002) | high | Bidirectional control characters (Trojan Source) |
| [UNI003](#uni003) | medium | Zero-width characters in code or agent instructions |
| [UNI004](#uni004) | high | Unusual variation-selector characters (possible hidden payload) |

### AGT001

**Credential hard-coded in an MCP server config** · severity: high · CWE-798

**Fix:** Reference an environment variable (e.g. "${GITHUB_TOKEN}") instead of pasting the value, and give the token the smallest scope that works.

### AGT002

**MCP server launched from an unpinned package** · severity: medium · CWE-1104

**Fix:** Pin an exact version (npx -y pkg@1.2.3, uvx pkg==1.2.3) so a malicious update can't run with your agent's permissions.

### AGT003

**MCP server given access to the whole disk or home folder** · severity: high · CWE-250

**Fix:** Point it at the one project folder it needs.

### AGT004

**Remote MCP server over unencrypted HTTP** · severity: medium · CWE-319

**Fix:** Use https:// for any MCP server that isn't on localhost.

### AGT005

**MCP server container runs privileged or with the Docker socket** · severity: high · CWE-250

**Fix:** Drop --privileged and don't mount /var/run/docker.sock or / into agent containers.

### AGT010

**AI agent approval prompts disabled** · severity: high · CWE-862

**Fix:** Keep a human in the loop: remove bypass/auto-approve modes from shared configs.

### AGT011

**AI agent pre-approved to run any shell command** · severity: high · CWE-250

**Fix:** Allow only the specific commands the agent needs, e.g. Bash(npm test:*).

### AGT012

**AI agent pre-approved for a risky command** · severity: medium · CWE-250

**Fix:** Require approval for destructive, network or deploy commands.

### AGT013

**All project MCP servers trusted automatically** · severity: medium · CWE-829

**Fix:** Approve MCP servers one by one; a cloned repo could add its own.

### AGT014

**AI agent run with approvals disabled in a script or CI** · severity: medium · CWE-862

**Fix:** Run unattended agents in a sandbox with read-only tokens, or restrict their tools.

### AGT020

**AI agent in CI triggered by untrusted input** · severity: medium · CWE-77

**Fix:** Issue/PR text is attacker-controlled prompt input. Limit the trigger to trusted authors (author_association) and give the job read-only permissions.

### AGT030

**Suspicious instruction in an AI agent rules file** · severity: high · CWE-77

**Fix:** Read the file carefully. Rules files are executed by the agent like code; treat changes to them like code review.

### UNI001

**Invisible Unicode tag characters (hidden AI instructions)** · severity: critical · CWE-1007

**Fix:** Delete the hidden characters. They smuggle text that AI models read but humans can't see.

### UNI002

**Bidirectional control characters (Trojan Source)** · severity: high · CWE-1007

**Fix:** Remove the bidi controls; they make code display differently from how it runs.

### UNI003

**Zero-width characters in code or agent instructions** · severity: medium · CWE-1007

**Fix:** Remove them; they can hide text or make identifiers look identical.

### UNI004

**Unusual variation-selector characters (possible hidden payload)** · severity: high · CWE-1007

**Fix:** Remove them; long runs of variation selectors can encode hidden data.

## Hallucinated or typosquatted dependencies

| ID | Severity | Rule |
|---|---|---|
| [SUP001](#sup001) | high | Possible typosquat of a popular package |
| [SUP002](#sup002) | high | Package does not exist on the registry (possible AI hallucination) |
| [SUP003](#sup003) | medium | Very new package (published in the last 30 days) |
| [SUP004](#sup004) | low | Dependency with no version constraint |
| [SUP005](#sup005) | medium | Dependency installed straight from a URL or git |
| [SUP006](#sup006) | medium | Remote script piped straight into a shell |
| [SUP007](#sup007) | low | Third-party GitHub Action not pinned to a commit SHA |

### SUP001

**Possible typosquat of a popular package** · severity: high · CWE-1357

**Fix:** Check the spelling. If you meant the popular package, fix the name before installing.

### SUP002

**Package does not exist on the registry (possible AI hallucination)** · severity: high · CWE-1357

**Fix:** Don't install it. The name was probably invented by an AI; an attacker could register it.

### SUP003

**Very new package (published in the last 30 days)** · severity: medium · CWE-1357

**Fix:** New packages with AI-plausible names are a common slopsquatting trap. Verify the publisher.

### SUP004

**Dependency with no version constraint** · severity: low · CWE-1104

**Fix:** Pin a version (and use a lock file) so a hijacked release can't slip in silently.

### SUP005

**Dependency installed straight from a URL or git** · severity: medium · CWE-494

**Fix:** Prefer a published, pinned release. If you must use git, pin to a commit SHA.

### SUP006

**Remote script piped straight into a shell** · severity: medium · CWE-494

**Fix:** Download, verify a checksum or signature, then run.

### SUP007

**Third-party GitHub Action not pinned to a commit SHA** · severity: low · CWE-829

**Fix:** Pin to the full 40-character commit SHA (tags can be moved by an attacker).

| [PQC012](#pqc012) | low | RSA key generation (quantum-vulnerable) |

| [PQC014](#pqc014) | info | secp256k1 wallet keys (quantum-vulnerable signatures) |

### PQC000

**Cryptography inventory** · severity: info

**Fix:** Use this list as the 'Discovery' step of a post-quantum migration plan.

### PQC001

**Weak hash (MD5/SHA-1) used** · severity: medium · CWE-328

**Fix:** Use SHA-256 or better; for passwords use argon2, scrypt or bcrypt.

### PQC002

**Broken cipher (DES/3DES/RC4/Blowfish)** · severity: high · CWE-327

**Fix:** Use AES-256-GCM or ChaCha20-Poly1305.

### PQC003

**ECB block-cipher mode** · severity: high · CWE-327

**Fix:** ECB leaks patterns in your data. Use GCM.

### PQC004

**RSA key shorter than 2048 bits** · severity: high · CWE-326

**Fix:** Use at least 3072-bit RSA now, and plan the post-quantum move.

### PQC005

**Outdated TLS/SSL version allowed** · severity: medium · CWE-326

**Fix:** Require TLS 1.2 minimum, ideally TLS 1.3 (which also enables hybrid PQ key exchange).

### PQC010

**RSA encryption/key transport (quantum-vulnerable)** · severity: medium · CWE-327

**Fix:** Plan migration to a hybrid post-quantum key exchange (e.g. X25519MLKEM768 in TLS) or ML-KEM (FIPS 203). Make the algorithm configurable so it can be swapped.

### PQC011

**Classical key exchange (ECDH/DH/X25519, quantum-vulnerable)** · severity: medium · CWE-327

**Fix:** Plan migration to a hybrid post-quantum key exchange (e.g. X25519MLKEM768 in TLS) or ML-KEM (FIPS 203). Make the algorithm configurable so it can be swapped.

### PQC012

**RSA key generation (quantum-vulnerable)** · severity: low · CWE-327

**Fix:** Plan migration to a hybrid post-quantum key exchange (e.g. X25519MLKEM768 in TLS) or ML-KEM (FIPS 203). Make the algorithm configurable so it can be swapped.

### PQC013

**Classical signature scheme (quantum-vulnerable)** · severity: low · CWE-327

**Fix:** Inventory where these keys live and how long they must stay trusted; plan for ML-DSA (FIPS 204) or SLH-DSA (FIPS 205) for long-lived signing keys.

### PQC014

**secp256k1 wallet keys (quantum-vulnerable signatures)** · severity: info · CWE-327

**Fix:** Exposed public keys on-chain can't be rotated retroactively. Avoid address reuse and track your chain's PQ roadmap.
